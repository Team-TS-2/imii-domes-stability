# .gitignore Configuration

This repository uses multiple .gitignore files at different levels to properly exclude files from version control.

## .gitignore Files

### 📁 Root `.gitignore`
**Location**: `/`

**Purpose**: Catches common files across the entire repository

**Ignores**:
- `node_modules/` - All dependency directories
- `.pnpm-store/` - pnpm's global cache
- `dist/`, `build/`, `cdk.out/` - Build outputs
- `.env*` - Environment files
- Editor files (`.vscode/`, `.idea/`)
- OS files (`.DS_Store`, `Thumbs.db`)
- Log files (`*.log`)
- CDK context (`cdk.context.json`)

### 📁 Front-End `.gitignore`
**Location**: `/front-end/`

**Purpose**: Front-end specific ignores

**Ignores**:
- `node_modules/` - Dependencies
- `dist/` - Vite build output
- `.env*` - Environment variables
- `.vite/` - Vite cache
- `*.tsbuildinfo` - TypeScript incremental builds
- Package lock files (keeps `pnpm-lock.yaml`)

### 📁 Back-End `.gitignore`
**Location**: `/back-end/`

**Purpose**: Back-end/CDK specific ignores

**Ignores**:
- `node_modules/` - Dependencies
- `cdk.out/` - CloudFormation synthesized templates
- `dist/` - Compiled TypeScript
- `*.js` - Compiled JavaScript files
- `!lambda/**/*.js` - EXCEPT Lambda function code (needed for deployment)
- `*.d.ts` - TypeScript declarations

## What IS Committed

✅ **Source Code**:
- All `.ts`, `.tsx` files
- All `.js` files in `lambda/` directories
- Component files
- Configuration files

✅ **Configuration**:
- `package.json`, `pnpm-lock.yaml`
- `tsconfig.json`, `vite.config.ts`
- `cdk.json`
- `.env.example` (template)

✅ **Documentation**:
- `README.md`, `DEPLOYMENT.md`
- All documentation files

✅ **GitHub Actions**:
- `.github/workflows/*.yml`

## What is NOT Committed

❌ **Build Artifacts**:
- `dist/`, `build/`, `cdk.out/`
- Compiled `.js` files (except Lambda)
- `.tsbuildinfo`

❌ **Dependencies**:
- `node_modules/`
- `.pnpm-store/`

❌ **Environment Files**:
- `.env`, `.env.local`
- Any file with sensitive credentials

❌ **IDE/Editor Files**:
- `.vscode/`, `.idea/`
- `*.swp`, `*.swo`

❌ **OS Files**:
- `.DS_Store` (macOS)
- `Thumbs.db` (Windows)

❌ **Logs**:
- `*.log`, `npm-debug.log*`

## Verification

To check what files are being ignored:

```bash
# See all ignored files
git status --ignored

# Check if a specific file is ignored
git check-ignore -v path/to/file

# List all tracked files
git ls-files
```

## Common Issues

### Issue: node_modules committed by accident
**Solution**:
```bash
git rm -r --cached node_modules
git commit -m "Remove node_modules from tracking"
```

### Issue: .env file committed by accident
**Solution**:
```bash
git rm --cached .env
git commit -m "Remove .env from tracking"
# Then rotate any exposed credentials!
```

### Issue: Build artifacts in repository
**Solution**:
```bash
git rm -r --cached dist/ cdk.out/
git commit -m "Remove build artifacts"
```

## Best Practices

1. ✅ Always create `.env.example` as a template (without real values)
2. ✅ Keep `.gitignore` files specific to their directory
3. ✅ Commit `pnpm-lock.yaml` for reproducible builds
4. ✅ Never commit credentials, API keys, or secrets
5. ✅ Review `.gitignore` before first commit
6. ✅ Use `git status` before committing to catch unignored files

## Related Files

- `.env.local` - Local development config (ignored)
- `pnpm-lock.yaml` - Lock file for dependencies (committed)
